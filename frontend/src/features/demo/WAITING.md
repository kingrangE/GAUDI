# 샘플 대기 화면과 저장된 실제 결과

## 사용자 흐름

공개 체험에서 기존 23개 POST 경로가 공통 `demoFetch → queuedFetch`를 사용한다.
접수한 작업 ID를 얻으면 전역 대기 패널이 나타난다. 페이지별 입력·문제·턴 화면을 교체하지 않는다.
패널을 접고 다른 내용을 둘러볼 수 있으며 새 작업부터 먼저 표시한다.
별도 로그인/새 세션 발급 없이 기존 HttpOnly 쿠키 소유자의 작업만 복원한다.
일반 모드(`NEXT_PUBLIC_DEMO_ENABLED` 미설정/false)는 대기 패널·세션 복원 요청을 사용하지 않는다.

1. 대기열/초기 단일 호출: 수치 없는 indeterminate 표시와 단계 설명.
2. 실제 완료 이벤트 수신: 기존 ProgressBar로 완료 단위 비율 표시. 남은 시간 추정치가 아님을 안내.
3. 중간 처리 단위가 모두 완료되어도 최대 99%. 시간이 지나서 퍼센트를 올리지 않는다.
4. 서버 completed 상태를 받은 뒤 결과 API와 네이티브 응답 envelope를 확인한다.
5. 실제 결과를 받은 경우에만 100%와 Live Report/이번 작업의 실제 결과로 전환한다.
6. 정상 실행에서는 네이티브 Response를 원래 호출자에게 돌려주어 기존 보고서·코드·생성물 흐름을 유지한다.

## 구현 경계

- `tracking.ts`: 소유자별 작업 관찰, 동일 ID의 진행/결과 조회 공유, React 외부 스토어.
- `jobs.ts`: 기존 멱등 요청 접수와 식별자 저장을 유지하며 관찰기에 연결. 저장된 ID의 재연결은 GET만 사용.
- `JobActivity.tsx`: 루트 QueryClientProvider 안의 공용 패널. 기존 레이아웃 위에서 닫기/접기를 제공하는 비모달 영역.
- `SampleReport.tsx`: 수작업으로 만든 별도 가상 사례. 사용자 결과·문제 은행·정답 fixture를 읽지 않음.
- `LiveResult.tsx`: 실제 네이티브 응답과 기존 리포트 컴포넌트 사용. CS/코딩/테스트 설계의 참조 응답은 허용된 본인 결과 API로 조회.
- `ProgressBar`: 기본 current/total 계약을 유지하고 접근성 progressbar, indeterminate, 99% 상한을 추가.

샘플에는 ‘미리 작성한 합성 예시’, 가상 사례명, ‘현재 문제의 정답이나 이번 입력의 평가 결과가 아님’을 표시한다.
실제 결과 전환 시 샘플 영역을 제거하고 출처를 ‘이번 작업에서 서버에 저장한 실제 결과’로 변경한다.
실행/생성 결과에 아직 점수가 없는 경우 임의의 점수를 만들지 않는다. 업무 추출은 반환 행만, 거부 능력 생성은 공개 텍스트만 표시한다.

모의고사는 전체 동작에서 별도 분기한다. 진행 상태와 제출/저장 확인만 표시하며 점수·채점 근거·정답을 렌더링하지 않는다.
종료 acknowledgement도 점수 공개로 해석하지 않는다. 기존 시험 화면의 공개 응답 필터링 계약을 유지한다.

## 재연결과 저장 정책

기존 `gaudi:pending-job:<owner>:<fingerprint>` 항목에 키·작업 ID·요청 pathname만 보관한다.
본문은 해시 지문 계산에만 쓰고 프롬프트·소스·점수·리포트·쿠키 값은 localStorage에 추가하지 않는다.
`gaudi:resource-job:<owner>:<fingerprint>`에는 준비 작업의 ID를 보관해 연습 session/run 생성 요청이 재진입 시 같은 자원을 재사용하게 한다.
path는 네이티브 결과 위치 식별용이며 임의 URL 이동/조회에 사용하지 않는다. 결과 추가 조회는 기능·ID·경로 정규식의 허용 목록을 사용한다.

루트 컴포넌트는 GET /api/demo/session으로 기존 소유자를 확인한 뒤 해당 소유자 prefix의 ID만 복원한다.
다른 소유자의 작업·응답은 화면에 병합하지 않으며 Query 캐시 키에도 소유자를 포함한다.
쿠키를 삭제한 방문자를 이전 방문자로 추정하거나 과거 결과를 보여주지 않는다.

동일 작업의 복구와 원래 요청이 겹쳐도 진행/결과 polling은 한 Promise를 공유하고 각 호출자에는 Response 복제본을 돌려준다.
원래 호출자의 AbortSignal은 호출자의 대기를 취소할 뿐 서버 작업을 중단했다고 표시하지 않는다.
서버 실패는 terminal로 종료하고 자동 평가 재시도를 하지 않는다. 네트워크/결과 수신 오류는 ID를 보존하고 ‘조회 다시 연결’로 GET만 재개한다.
초기 세션 확인이 오프라인이어도 재조회할 수 있다. 소유권 401/404는 결과 API를 호출하지 않는다.

**복구 범위:** 접수 확인 후 저장한 작업 ID의 진행·실제 결과를 새로고침 후 복원한다.
아직 작업 ID를 받지 못한 응답 유실은 원래 입력을 다시 제출할 때 저장된 같은 멱등 키로 복구한다. 입력 없이 자동 POST하지 않는다.
제출하지 않은 편집 초안이나 페이지 전체 폼 상태는 복원하지 않는다. 기존 평가 화면의 준비 요청은 같은 생성 작업을 재조회해 session/run ID를 재사용한다. 내부 폼의 모든 선택·작성 상태까지 복원하는 것은 아니다.
결과·실행물의 공용 복구 화면과 페이지 전체 작성 상태 복구를 구분하며, 재시작할 필요 없이 확인 가능한 저장 결과를 우선 제공한다.

## 검증 및 배포

네이티브 작업 응답 계약은 그대로 유지하며 새 백엔드 API·테이블·LLM 호출은 추가하지 않는다.
프론트 단위 검증은 합성/실제 출처, 완료 전 100% 금지, 관찰 공유, 실패·재연결·소유자 변경,
AbortSignal, 저장된 본인 ID 복구, 전체 기능 결과 표시, 모의고사 비공개를 포함한다.
실제 유료 LLM·운영 EC2·브라우저 E2E는 이 검증에 포함하지 않는다.

이 브랜치는 최신 main에서 시작했다. 시작 시 PR #67(비용·횟수 제한)이 OPEN이므로 해당 정책을 복사하지 않았다.
공개 활성화 전 두 기능을 main에 통합해야 한다. `jobs.ts` 공통 변경은 병합 순서에 따라 재베이스/충돌 확인이 필요하다.

최종 검증(2026-11-05): backend 540 passed / 12 skipped, frontend 259 passed.
ruff·ESLint·TypeScript·Next.js production build 통과. 실제 유료 LLM·EC2·브라우저 E2E 미실행.
브라우저 연결 불가 및 native UI 도구 타임아웃으로 시각 검증은 완료하지 못했다.
