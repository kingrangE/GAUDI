# 개발 프롬프팅 (feature_dev_prompting)

> **상태:** 추상 명세 (구현 전). "무엇을 만들 것인가"만 정의한다.
> **담당:** BE / minsu
> **평가 항목:** 개발 프롬프팅 · **측정 역량:** 알고리즘 이해 · **산출물:** 해결 여부·이해도
> (README ① "AI Agent 활용 개별 역량" 표 참조)

## 1. 목적 (무엇을 측정하나)

응시자가 **어려운 알고리즘 문제를 AI만으로 풀어내는 프롬프팅·문제 분해 역량**을 측정한다.
응시자는 **코드를 직접 수정할 수 없고**, 오직 AI에게 주는 지시(프롬프트)만으로 정답에
도달해야 한다. 이를 통해 "스스로 코드를 짜는 능력"이 아니라 **알고리즘을 이해하고 그것을
AI에게 정확히 지시·검증하는 능력**을 분리해 평가한다.

- 난이도: **백준 골드 3~4 / 프로그래머스 Lv2(어려운 것)~Lv3(쉬운 것)** 수준.

## 2. 평가 아이디어 (핵심 메커니즘)

1. 어려운 알고리즘 문제 1개를 제시한다 (설명·제약·예제 입출력).
2. 응시자는 **프롬프트만으로** AI에게 풀이를 지시한다. **코드 직접 편집은 차단**한다.
3. AI가 생성한 코드를 **샌드박스에서 실행**하고 **테스트케이스(히든 포함)로 채점**한다.
4. (멀티턴 허용 시) 실패 결과를 응시자에게 피드백하고, 제한된 횟수 내 **재프롬프트**를 허용한다.
5. 통과한 테스트 비율과 시도 양상을 바탕으로 **해결 여부·이해도**를 산출한다.

> 핵심 제약: **응시자는 코드를 못 만지고, AI에게 시키기만 한다.**

## 3. 입력 / 출력 (추상 계약)

**입력**
- 문제 정의 (설명 · 제약 · 공개 예제)
- 응시자 프롬프트 (턴별)
- 채점 테스트케이스 (공개 + 히든)
- 실행 설정: 사용 모델(고정), 멀티턴 허용 횟수, 실행 타임아웃 — 백엔드 중앙 config에서 주입

**출력**
- 통과 테스트 수 / 총 테스트 수, 통과율
- 사용 턴 수 · 시도 로그
- **해결 여부 + 이해도** 종합 점수와 근거

## 4. 처리 흐름 (추상)

```
문제 제시
  → 응시자 프롬프트 입력 (코드 편집 불가)
  → 고정 모델로 코드 생성
  → 샌드박스 실행 → 테스트케이스 채점
  → (실패 & 턴 남음) 피드백 후 재프롬프트 루프
  → 통과율·턴 수 기반 해결 여부·이해도 산출
```

## 5. 점수화 개념 (확정은 구현 단계에서)

- **해결 여부**: 전체(특히 히든) 테스트케이스 통과율.
- **이해도(보조)**: 정답 도달까지의 턴 수·프롬프트의 알고리즘 지향성(접근을 정확히 지시했는지).
- 두 축을 결합해 종합 점수 산출.

## 6. 풀어야 할 결정 사항 (Open questions)

- 문제 출처·저작권(자체 출제 vs 외부 문제) 및 문제 풀 구성.
- 코드 실행 샌드박스 환경(언어·리소스·타임아웃 격리)과 보안.
- 멀티턴 허용 정책(횟수·피드백 노출 범위)과 코드 직접 편집 차단 보장 방식.
- 사용 모델 고정 정책(약한 모델로 고정해 모델 자체 능력 의존을 줄일지).

## 7. 공통 제약 (리포 규칙)

- 모델 선택/호출은 **백엔드 중앙 config**에서 주입. 시크릿은 `.env`만.
- 단위 테스트에서 **LLM·샌드박스 실행을 목킹**: 채점·집계·턴 제어 로직을 결정적으로 검증.
  실모델/실행 통합 테스트는 소수만.
- 독립 폴더 개발 후 공용 evaluator 인터페이스로 플랫폼에 **조립**.

## 8. 구현 현황 (MVP)

확정된 설계 결정과 현재 코드 매핑:

| 결정 | 선택 | 위치 |
|---|---|---|
| Solver 모델 | OpenAI 소형 **고정** (기본 `gpt-4o-mini`, env override) | `backend/llm/config.py`, `backend/llm/client.py` (중앙 config) |
| 코드 실행 | 로컬 **subprocess + 제한**(wall timeout, POSIX CPU/메모리 rlimit) | `sandbox.py` |
| 진행 방식 | **멀티턴** N회 재프롬프트 (정답 시 조기 종료, 턴별 피드백) | `evaluator.py` |
| 채점 | 히든 포함 테스트 통과율(해결 여부 70%) + 턴 효율(이해도 30%) | `grader.py` |

- 모듈: `models` · `sandbox` · `solver`(LLM seam) · `grader` · `evaluator` · `problems`(샘플 2개) · `api`(FastAPI 라우터, 조립용).
- 응시자 코드 직접 편집 불가 → 입력은 **프롬프트 리스트**뿐. 히든 케이스의 기대/실제 출력은 피드백에서 **redact**.
- 테스트(`backend/tests/test_dev_prompting_*.py`): 샌드박스·grader·evaluator·API. LLM은 fake client로 목킹, 샌드박스는 실제 subprocess 실행.

### 남은 작업 (조립/후속)
- 라우터를 메인 FastAPI 앱에 mount (전체 기능 조립 단계).
- 더 강한 격리(Docker/네트워크 차단) 및 실행 언어 확장.
- 프롬프트의 알고리즘 지향성 기반 이해도 채점(현재는 턴 수 프록시).
- 실제 골드 난이도 문제 풀 확보(저작권 고려).
- solver 실모델 통합 테스트 1~2개(키 있을 때만, skip 마커).
