# 공개 체험의 사용량·비용·실행 제한

## 적용 범위와 사용자 계약

`DEMO_ENABLED=true` 및 `DEMO_LIMITS_ENABLED=true`일 때만 적용한다. 기본 일반 모드는 기존 동작을 유지한다.
8개 개별 평가와 모의고사를 각각 **선택적으로 최대 1회** 체험한다. 모든 기능을 사용할 의무는 없다.
문제 목록·설명·기존 결과 조회, 개발 run 및 연습 session 생성은 유료 체험을 차감하지 않는다.
첫 실제 실행·평가부터 기능의 한 체험을 고정한다. 다른 문제나 session으로 바꿔 다시 평가할 수 없다.
모의고사는 시작 시 전체 과정을 예약하며 하위 평가를 개별 연습 횟수에 중복 차감하지 않는다.

- 컨텍스트·명세·CS: 최초 평가 입력 고정, 완료 후 다시 요청하면 기존 결과를 반환한다.
- 개발 프롬프팅: 하나의 run에서 최대 20턴. 일괄 평가 입력도 최대 20개다.
- 코딩: 하나의 문제, 샘플 실행 최대 20종 입력과 최종 제출 1회.
- 업무 프롬프팅: 하나의 session 안에서 기존 문제별 최대 3회 실행을 유지한다. 같은 프롬프트도 재실행 가능하다.
- 거부 능력: 하나의 session 안에서 주제별 생성 최대 2회와 최종 채점 1회.
- 테스트 설계: 하나의 session 안에서 문제별 제출 1회. 나머지 문제를 강제로 완료할 필요는 없다.
- 실패한 동일 논리 단계는 동일 입력으로 기본 1회 재접수 가능하다. 입력 변경은 충돌로 처리한다.
- 같은 Idempotency-Key는 원래 작업을 반환한다. 새 키를 써도 완료된 단발 평가는 다시 실행하지 않는다.
- 동일 기능의 새 단계는 이전 작업 종료 후 접수한다. 서로 다른 기능은 세션 작업 상한 안에서 접수할 수 있다.

`GET /api/demo/usage`는 자신의 기능별 `available / active / completed`와 남은 새 체험 횟수를 반환한다.
시작한 단계형 체험은 `remaining=0`이어도 이어갈 수 있다. 개발·테스트 설계는 명시적 종료가 없어 만료 시까지 active다.
브라우저 쿠키를 지우면 새 방문자가 될 수 있으므로 익명 세션만을 사람 단위 인증으로 간주하지 않는다.

## 금액 장부와 사전 예약

`DemoBudget` 단일 행을 UPDATE하여 PostgreSQL 트랜잭션 행 잠금을 얻는다. 신규 체험, 작업·단계 및 요청 키의 결과 연결 저장,
전역/세션 대기열 확인을 같은 트랜잭션에서 처리한다. 두 웹 프로세스가 동시에 요청해도 예산을 이중 예약하지 않는다.
금액은 부동소수점 대신 정수 nano-USD(1달러=10억 단위)를 사용한다.

운영자가 설정한 모델별 USD/100만 입력·출력 토큰 단가를 올림 변환한다. 새 체험 예약액은:

```
기능 최대 호출 수 × (입력 토큰 상한 × 가장 높은 입력 단가 + 출력 토큰 상한 × 가장 높은 출력 단가)
```

실패 재시도 몫을 포함한다. 개별 모델의 실제 출력 제한이 더 작아도 최초 체험은 보수적으로 전체 상한을 예약한다.
공식 모델 가격을 확인해 설정해야 하며, 구현에는 임의의 실제 단가나 실제 운영 금액을 넣지 않았다.
`DEMO_DAILY_BUDGET_USD=0`, 단가 미설정/비양수는 유료 작업을 503으로 차단한다.
따라서 공개 전 금액·단가 설정이 필요하다. 예산이 한 체험 예약액보다 작으면 그 기능은 시작할 수 없다.

최대 호출 수(명시적 작업 재시도 기본 1회이면 아래 값의 2배):

| 기능 | 정상 1회 호출 상한 |
|---|---:|
| 컨텍스트 | 4 (coverage 3 + boundary 1) |
| 명세 | SPEC_SAMPLES × 2 |
| 개발 | 20 |
| 코딩 | 1 |
| CS | 전체 질문 수 + 종합 리포트 1 |
| 업무 | 전체 문제 수 × 3 |
| 거부 | 전체 주제 수 × (생성 2 + 채점 1) |
| 테스트 설계 | 전체 문제 수 |
| 모의고사 | 컨텍스트 4 + 명세 SPEC_SAMPLES × 2 + 거부 3 + 테스트 1 + 개발 20 |

각 실제 LLM 호출 직전에 체험 예약액을 `reserved → inflight`로 옮겨 DB에 커밋한 뒤 전송한다.
동기 OpenAI 및 비동기 structured-output 경로 모두 보호하며, 중첩 스레드풀에도 서버 실행 컨텍스트를 전파한다.
SDK 내부 자동 재시도는 데모에서 0으로 두어 계측되지 않는 재전송을 막는다. 명시적 실패 작업 재시도만 허용한다.
모든 프롬프트·시스템 지시·출력 스키마 JSON의 UTF-8 바이트 합에 framing 여유 1,024를 더해 입력을 보수적으로 제한한다.
출력은 `max_tokens` 또는 `max_completion_tokens`로 제한한다. 이미지/파일 입력 경로는 지원하지 않는다.

반환 usage가 유효하면 호출 시 저장한 단가로 정산하고 차액을 체험 예약으로 환급한다.
타임아웃·usage 누락·형식 오류·범위 초과는 호출 상한 전액을 `unknown` 지출로 잡는다. 무료였다고 추정하지 않는다.
남은 예약은 최종 제출·채점 완료 또는 실행 중 작업과 슬롯이 없는 만료 체험 정리 시 반환한다.
UTC 날짜가 바뀌어도 예약과 미정산 노출은 보존하고 확정 지출만 초기화한다.

이는 **설정 단가에 따른 애플리케이션 지출 통제**다. 공급자 가격 변경·별도 API 키 사용·다른 서비스 청구·세금/환율은
이 장부에서 통제할 수 없다. 가격·토큰 정책·한도는 모든 웹/워커에 동일하게 배포하고 진행 중 임의로 바꾸지 않는다.
실제 운영액은 배포 전 운영자가 선택하고 한 체험 예약액 이상인지 확인한다.

## 동시 실행과 장애 회수

기본 전역 평가 1개, 실제 Docker 실행 1개, 전역 queued 20개, 세션 queued+running 2개다.
DB `DemoSlot`의 조건부 임대 기록을 사용해 여러 RQ 프로세스에서도 제한을 공유한다.
각 컨테이너 이름을 샌드박스 슬롯에 저장한다. Docker 종료가 확인되어야 슬롯을 반환하며 확인 불가 오류에는 유지한다.
스레드 작업은 취소가 즉시 전파되지 않으므로 worker는 shield 후 실제 종료까지 기다린다.
명세의 병렬 생성·채점도 형제 작업이 실패했다고 남은 스레드를 기다리지 않고 반환하지 않는다.

관리자 `POST /api/demo/jobs/recover`는 기존 전달 복구 외에 슬롯 회수를 시도한다.
같은 hostname에서 저장된 PID가 사라졌음을 확인한 경우만 자동 회수한다. sandbox는 Docker 목록 조회 성공과
남은 컨테이너 강제 제거 성공까지 확인한다. Redis의 failed/finished 상태나 임의 TTL만으로 살아 있는 작업을 회수하지 않는다.
미정산 호출은 상한 전액으로 정산하며 오래된 lease의 결과 저장·슬롯 반환을 차단한다.
원격 호스트/다른 hostname, PID 재사용, 살아 있는 PID에서 발생한 정리 실패는 자동 회수하지 않고 unresolved로 남긴다.
운영자가 실제 프로세스·컨테이너 종료를 확인한 후 복구해야 한다. 자동 재실행으로 유료 호출을 중복시키지 않는다.

새 테이블만 추가하므로 기존 평가 원본 컬럼 변경이나 데이터 삭제는 없다. 기존 create_all 초기화 경로로 등록된다.

## 세션 발급과 프록시

IP 해시+UTC 시간 버킷별 새 세션 발급을 기본 시간당 10회로 제한한다. 유효 쿠키 갱신은 새 발급으로 세지 않는다.
X-Forwarded-For는 기본적으로 무시한다. 직접 연결한 peer가 `DEMO_TRUSTED_PROXIES` CIDR에 포함될 때만
오른쪽부터 신뢰 가능한 프록시를 벗겨 실제 주소를 선택한다. 프록시/uvicorn 설정에서도 외부의 임의 헤더를 신뢰하지 않아야 한다.
공유 NAT 사용자는 한도를 공유할 수 있고 다중 IP 공격은 가능하지만 일일 금액 상한을 우회하지는 못한다.
