# 전체 평가의 공용 작업 연결

작성일: 2026-11-04

8개 개별 평가와 모의고사의 변경 요청 23개를 공용 작업 경로에 연결했다.
문제·자료·기존 결과 조회 GET은 기존 경로를 유지한다. 최종 공개 범위는 전체 기능이며,
회원가입 없이 둘러보고 관심 있는 기능만 각각 최대 1회 이용하는 정책은 다음 사용량 단위에서 적용한다.

## 실행 흐름과 기존 계약

공개 모드에서 기존 POST 경로는 `DemoRoute`를 통해 입력·소유권·중복 키를 검사하고
작업을 저장한 뒤 `202 + job_id`로 응답한다. 유효한 쿠키가 있어도 중복 키가 없으면
`428`이며, 기존 HTTP 경로를 직접 호출해 인라인 평가를 실행할 수 없다.

`operations.py`가 허용하는 기능·동작·경로·입력 스키마만 실행할 수 있다.
클라이언트가 실행할 함수나 임의 URL을 지정하지 못한다. 작업 API의 기존 컨텍스트
`evaluate` 입력은 호환성을 유지하고, 나머지 동작은 다음 형식으로 접수한다.

```json
{
  "feature": "test_design",
  "action": "submit",
  "input": {
    "params": {"session_id": "본인 세션 ID", "problem_index": 0},
    "body": {"flaws": ["찾은 설계 결함"]}
  }
}
```

워커는 같은 프로세스 안의 ASGI 앱으로 기존 허용 API를 실행한다. 기존 API를 호출하는 구간에는 외부 HTTP 네트워크를
사용하지 않는다. LLM 공급자 호출은 기존 모델·설정을 따른다. 기존 FastAPI 입력·응답 모델, 접근 검사, 채점 로직을 재사용하므로
평가 코드나 시험 중 비공개 응답을 별도로 복제하지 않는다.

실행 신원과 작업별 DB 세션 팩토리는 서버의 `ContextVar`로만 전달한다.
HTTP 헤더로 실행 권한을 얻을 수 없으며, 실제 기존 API 실행에서도 자원 소유권을 확인한다.
작업 종료 시 문맥을 반드시 복원한다. 워커 내부 DB 접근은 해당 작업의 세션 팩토리를 사용한다.

기존 코딩·CS의 `grading_mode=rq` 설정에서도 공용 워커 내부 채점은 인라인으로 실행한다.
같은 평가를 다시 기존 grading 큐에 넣지 않으며, 네이티브 자원 채점 실패를 성공 작업으로
취급하지 않는다. 공개 오류에는 원본 공급자 예외 대신 일반 오류 코드·HTTP 상태를 제공한다.

네이티브 작업 결과는 `{ "http_status": 201, "body": { ... } }`로 저장한다.
기존 직접 컨텍스트 `evaluate` 작업의 결과는 이전 리포트 형식을 유지한다.
프론트엔드 공통 클라이언트가 작업을 조회하고 네이티브 상태·JSON을 복원하여
기존 화면·React Query 호출자가 기존 응답 형식을 계속 사용하게 했다.

## 진행 상태와 시험 시간

| 기능 | 실제 완료 이벤트 |
|---|---|
| 컨텍스트 | 정적 두 축·커버리지·경계 평가 |
| 명세 설계 | 생성된 샘플 수·분석된 샘플 수·점수 집계 |
| 개발 프롬프팅 | 코드 생성·턴 테스트 완료 |
| 코딩 테스트 | 완료한 테스트 케이스·코드 분석 |
| CS 평가 | 문항 채점·통합 리포트 생성 |
| 거부 능력 | 설계 생성·채점한 주제 수 |
| 테스트 설계 | 결함 매칭·결과 저장 |
| 사무직 | 데이터 추출·결과 저장 |
| 모의고사 | 해당 단계 코어의 이벤트 및 단계 결과 저장 |

시간 경과로 진행률을 올리지 않으며 결과 저장 전에는 최대 99%다.
짧은 세션 생성·제출 확정 같은 작업은 별도의 가짜 중간 단계를 만들지 않는다.

시험 시간은 입력을 접수한 시각을 작업에 보존하고, 내부 채점 요청에서는 그 시각을
기준으로 검사한다. 마감 전에 접수했지만 큐에서 기다린 답안을 단순히 늦게 처리됐다는
이유로 거절하지 않는다. 마감 후 새로운 답안은 접수 단계에서 거절한다.
기존 답안 재시도·저장된 개발 실행 최종 확정·시험 종료 규칙은 유지한다.
일반 브라우저 상태 조회는 현재 시각으로 남은 시간을 계산한다.
모의고사의 작업 결과에도 기존 공개 응답만 저장하여 응시 중 점수·정답을 숨긴다.

## 브라우저 재시도와 남은 UI 범위

공개 모드의 모든 평가 API 클라이언트가 사용하는 `demoFetch`에서 작업 접수·polling을
처리한다. 전송 전 생성한 중복 키와 접수 후 작업 ID를 세션별로 저장한다.
저장 키에는 URL·본문의 SHA-256 지문을 사용하며 원본 답안이나 인증 토큰은 저장하지 않는다.
응답이 유실되면 같은 키로 재접수하고, 작업 ID가 있으면 POST 없이 기존 작업을 조회한다.
실패·세션 만료 시 자동 평가 재실행은 하지 않는다.

같은 세션·같은 입력으로 해당 호출이 다시 수행될 때 이어서 조회할 수 있는 클라이언트
기반까지 구현했다. 페이지별 입력·네이티브 세션 복원, 재접속 안내, 샘플 리포트 대기 화면과
화면의 Progress Bar는 후속 UI 단위다. 이 기반만으로 모든 페이지가 자동 복원된다고 보장하지 않는다.
