# 공개 체험 세션과 결과 소유권

포트폴리오 공개 체험의 첫 구현 단위다. 방문자는 회원가입이나 고정 응시 코드 없이
둘러볼 수 있다. 평가 결과의 접근 권한은 서버가 발급한 체험 세션에 귀속된다.

## 구현한 계약

- `POST /api/demo/session`: 새 세션 발급 또는 유효한 기존 세션 갱신.
  갱신은 세션 ID와 연결된 자원을 보존한다. 응답은 세션 ID와 만료 시간이며 토큰은 포함하지 않는다.
- `GET /api/demo/session`: 현재 유효한 세션 정보. 쿠키 누락·위조·만료는 `401`.
- 원본 토큰은 32바이트 난수이며 HttpOnly, SameSite=Lax, host-only 쿠키로만 전달한다.
  DB에는 SHA-256 해시와 만료 시간을 저장한다. 성공 응답은 `Cache-Control: no-store`다.
- 문제·프로젝트 목록/상세 조회는 세션 없이 허용한다. 공개 모드의 모든 기능 실행·생성은
  유효한 세션을 요구하며, 변경 요청의 Origin은 설정한 CORS 목록과 대조한다.
- 기존 테스트 설계·거부 능력·사무직·CS 세션, 코딩 제출, 개발 실행, 모의고사는
  원본 자원과 소유권 매핑을 같은 DB 트랜잭션에서 저장한다. 채점 큐 전달 전에 매핑이 존재한다.
- 다른 세션 또는 소유권 매핑이 없는 자원에 대한 조회·변경은 `404`다.
  응시자 이름·고정 코드·관리자 토큰은 공개 자원의 소유권 검사를 우회하지 못한다.
- 모의고사는 서버 세션으로 응시자 식별자를 만든다. 기존 시험의 응시 중 점수 비공개와
  관리자 인증은 유지한다. 하위 시험 자원은 소유권을 검사한 시험 경로를 통해 접근한다.
- 명세·컨텍스트·일괄 개발 평가는 현재 별도 결과 조회 자원이 없는 요청/응답 방식이다.
  실행 요청에 세션을 요구한다. 2차 공용 작업 API는 컨텍스트 평가의 원본·결과 저장을
  지원하며, 나머지 기능과 기존 화면의 전환은 후속 단위에서 연결한다.
- 프론트엔드의 모든 평가 API 클라이언트는 공개 모드에서 쿠키를 전송한다.
  같은 문서 안의 동시 요청은 한 번의 세션 발급을 공유하며, 만료 오류에서 평가를 자동 재전송하지 않는다.

## 설정과 배포 전제

기본값은 기존 운영 방식이다. `DEMO_ENABLED=true`와 프론트엔드 빌드 시
`NEXT_PUBLIC_DEMO_ENABLED=true`를 함께 설정해야 공개 입장이 활성화된다.
`DEMO_SESSION_SECONDS` 기본값은 7200이며 유효한 세션 갱신 시 같은 ID의 만료 시간만 연장한다.

운영 환경은 HTTPS와 같은 사이트 내의 프론트엔드/API를 사용한다. 예를 들어 동일 도메인의
리버스 프록시 또는 같은 상위 도메인의 웹/API 구성을 사용하고, `CORS_ORIGINS`에는 실제
프론트엔드 origin을 명시한다. 모든 프론트엔드 API base 설정은 같은 백엔드를 가리켜야 한다.
`DEMO_COOKIE_SECURE` 기본값은 true이며 로컬 HTTP 테스트에서만 false로 설정한다.

새 테이블은 기존 시작 시 `create_all()` 경로로 생성한다. 기존 평가 테이블을 변경하거나
기존 결과를 자동으로 특정 방문자에게 귀속하지 않는다. 공개 모드에서 기존 미귀속 자원은 접근할 수 없다.

## 후속 구현 경계

1차 PR은 세션과 소유권을 구현했다. 2차 작업 저장·진행률·큐·복구와 컨텍스트 실행은
[공용 작업 명세](JOBS.md)에 기록한다. 기능별 최대 1회, 세션 발급 빈도 제한,
서버 전체 비용 예산, 전체 기능의 공용 작업 전환, 종료 후 본인 모의고사 Live Report,
샘플 대기 화면, 보관·정리는 아직 구현하지 않았다. 비용 보호까지 완료하기 전에는
이 설정만으로 인터넷에 공개하지 않는다.

최종 이용 원칙은 **자유롭게 둘러보고 원하는 기능만 각각 최대 1회**다. 모든 기능을
완료할 의무는 없으며, 기능 내부의 기존 턴·실행은 하나의 체험에 포함한다.
